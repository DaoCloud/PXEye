# 安装任务

[English](installation-tasks.md) · **简体中文** · [页面使用指南](README.zh-CN.md)

## 1. 用途与入口

进入 **装机 → 安装任务**，执行首次安装或重装，并跟踪每台设备的进度、日志和结果。开始前准备可用的 OS、已发布安装方案、设备配置及[装机前检查](../pre-installation-checklist.zh-CN.md)要求的连通性。

## 2. 字段填写

安装向导使用设备已保存的配置，分为**选择设备**和**核对配置**两步。

| 项目 | 填写 / 核对要求 |
| --- | --- |
| 设备选择 | 可按 SN、架构、管理子网、当前系统筛选；每批最多 50 台。已有活动任务或尚未完成回收的设备不可选择。 |
| 查询当前系统 | 查询已选设备；未选择时查询当前筛选设备，范围为 1–50 台。查询结果用于核对当前系统。 |
| 目标 OS / 方案 | 来自设备的系统配置；OS 架构须与目标主机及方案一致。 |
| 主机名 / 管理地址 | 来自设备配置；管理接口、地址和子网必须对应。 |
| 系统盘 | 显示设备指定盘或方案选盘结果；需 Scout 回报后确定时，留意后续选盘结果和清理范围。 |
| 并发数 | 来自[站点设置](site-settings.zh-CN.md)，创建批次时固定。 |
| 执行确认 | 核对设备、地址及系统盘，并允许安装和重启；涉及首次接入清理时还须确认全部磁盘清理范围。 |

## 3. 操作步骤

### 创建并跟踪

1. 点击**新建安装任务**，选择设备，按需**查询当前系统**，点击**下一步**。
2. 核对逐台配置及预检结果；需要修改时点击**编辑设备规划**，保存后重新核对。预检失败须先解决对应问题。
3. 阅读影响范围，完成确认，点击**确认并安装**。系统按每台设备状态选择首次安装或重装路径，并保存本次配置快照。
4. 在批次中点击**逐台查看**；在单机记录中查看**实时安装日志**、**执行与恢复记录**和**安装验收**。
5. 完成后查看系统盘、固定网络、SSH 及普通重启验收结果；有报告时点击**下载验收报告**保存。

### 处理失败

点击任务的**处理问题**，按当前阶段提供的入口操作：

| 入口 | 使用场景 / 影响 |
| --- | --- |
| 查看自动修复 / 恢复进度 | 查看正在执行的恢复步骤或安装结果观察，先核对进度和日志。 |
| 开始验收 | 在故障处理页右下角点击；核对 SN 并允许启动、重启验证后，直接启动原任务验收。恢复进度不阻挡此入口；仍须具备本轮可信身份，所有验收项照常检查，不重新写盘。 |
| 继续准备设备 | 使用当前设备规划继续接入准备；按弹窗确认清理范围。 |
| 重试安装 / 重新检查并继续 | 复用原 Instance 和原任务规划；重新预检并确认，继续安装可能再次覆盖系统盘。 |
| 结束任务 | 释放 PXEye 任务占用并保留历史；不会停止物理机安装程序，也不回收 NICo Instance。 |

## 4. 填写示例

为 `SERIAL-1` 保存主机名 `gpu-01`、管理地址 `192.0.2.10`、已发布的 Ubuntu 方案及系统盘 `DISK-001`。新建任务选中该设备，在核对页确认这些值及清理范围，再提交安装。

## 5. 注意事项

- 首次接入可能清理全部磁盘，包括非系统盘；不能仅凭最终选中的系统盘判断清理范围。
- 一台失败会暂停该设备的任务，其余设备继续执行；不要重复创建任务来绕过待处理状态。
- 已创建任务使用配置快照；后续编辑设备或方案不会自动改变本轮安装。 删除网口地址后，验收仍会按本轮规划报告缺失地址。
- “系统盘与 EFI 分区验证”通过 SSH 只读核对根分区、EFI 分区及分区方案；不调整固件启动顺序。
- “排队”“运行中”或已创建 Instance 均不表示 OS 安装完成；以安装与启动验收结果为准。

### GPU 环境检查（可选）

在安装方案的“安装验收”中勾选“GPU 环境检查”，保存并发布新版本。开关随本轮任务冻结；旧方案默认关闭，验收界面显示灰色“已跳过”。这项检查仅在基础安装验收通过后、普通重启验收之前读取状态，不执行 GPU 测试或部署脚本。

部署脚本需原子写入 `/var/lib/metal-deployer/state.json`：先写同目录临时文件再 rename。文件最大 256 KiB，`schema` 为整数 `1`，`iso_version` 为非空版本文本；`boot_id` 取部署首启时的 `/proc/sys/kernel/random/boot_id`。建议附带从 `/etc/nico-installation.json` 读取的 `task_id`；提供后必须匹配当前任务。`started_at`、`updated_at` 使用带时区的 ISO 8601 时间，需属于本轮安装；节点时钟应同步。

`overall` 和每个阶段 `status` 使用 `pending/running/success/failed`。`stages` 必须非空且名称唯一，`current_stage` 非空时必须存在于清单；结束阶段必须有整数 `rc`，成功阶段为 `0`。可提供 `start/end/log`，日志路径仅展示。只有 overall=success 且所有阶段 success/rc=0 才通过；失败、协议错误或身份不符进入“需处理”。缺文件或 SSH 暂不可达每约 10 秒重读一次，单次 SSH 最长 20 秒，每次验收最多等待 60 分钟。`updated_at` 不用于单独推断卡死。

通过后保存状态摘要及首启 boot_id，再进入普通重启验收；重启后使用已验证回执，不要求历史状态文件改写为新 boot_id。失败后的“开始验收”只重新观察，不重装、不重跑脚本。若服务在重启前没有成功回执，不能通过最终验收。

安装验收文案统一为：安装器成功 → 主机配置 → 系统盘与 EFI 分区验证→ 网络配置 → SSH 连通 → DNS / HTTP / NTP 连通 → GPU 环境检查（可跳过）→ 重启验收。“系统盘与 EFI 分区验证”核对 root 和 ESP 位于目标盘，不表示再次修改固件启动顺序。原有环境服务必选/告警策略不变。GPU 状态属于自定义部署协议，不等同于 cloud-init 标准状态。
