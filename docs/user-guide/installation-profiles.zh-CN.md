# 安装方案

[English](installation-profiles.md) · **简体中文** · [页面使用指南](README.zh-CN.md)

## 1. 用途与入口

进入 **配置 → 安装方案**，统一设置一组服务器的 OS、选盘规则、分区及登录默认值。设备在**系统配置 → 当前安装方案**选择具体版本；逐机主机名、管理接口和固定地址在设备配置维护。

## 2. 字段填写

### 基本信息、磁盘及登录

| 字段 | 填写要求 |
| --- | --- |
| 方案名称 / 说明 | 名称必填，最多 100 字符；说明最多 1000 字符。 |
| 默认 OS | 选择已登记、已启用且与方案架构相同的 Ubuntu Server OS。 |
| 选择规则 / 候选范围 | 唯一匹配、容量最小或容量最大；范围为所有磁盘或仅 NVMe。设备明确指定盘时优先使用指定盘。 |
| 序列号 / 型号规则 | 可选；`*` 匹配任意字符，`?` 匹配单个字符，区分大小写；所有筛选条件同时生效。 |
| 最小 / 最大容量 | 可选，单位 GiB；容量规则需要完整的 Scout 容量信息，最小值不能大于最大值。 |
| 根分区格式 | `ext4` 或 `XFS`。 |
| EFI 分区 | 整数 `512–4096` MiB，默认 `1024`。 |
| 根分区 | 留空使用剩余空间；指定时至少 `20` GiB，多余空间不分配。 |
| OS 用户名 | 普通用户，最多 32 字符；以小写字母或 `_` 开头，后续可用小写字母、数字、`_`、`-`，不能为 `root`。 |
| 登录方式 / 默认密码 | 选择 SSH 密码或公钥登录；密码可在方案或逐台设备配置，已有密码留空保留。**默认密码处理**可显式清除密码。 |
| SSH 公钥 | 每行一条完整公钥；公钥登录时最终配置须有有效公钥。 |

### 按需配置

展开**高级设置**填写：

| 字段 | 填写要求 |
| --- | --- |
| 时区 | IANA 时区，例如 `Asia/Shanghai`。 |
| NTP 服务器 | 每行一个可达地址或主机名；发布方案时须填写。 |
| 额外软件包 | 每行一个包名；安装所需依赖须在 ISO 或配置的软件源中可用。 |
| APT 软件源 / 安全更新源 URL | 填写目标系统架构对应的可达源；离线安装留空时仅使用 ISO 材料。 |
| DNS 验收域名 / HTTP 验收 URL | 每行一项，在安装验收时检查服务；DNS 验收域名不是 DNS 服务器配置。 |

## 3. 操作步骤

1. 点击**新建方案**，或**复制**已有方案，填写配置后**保存草稿**。
2. 重新打开草稿，点击**检查方案**，解决缺少 OS、用户名、NTP 或材料不兼容等问题。
3. 点击**发布版本**。发布后在设备**系统配置**选择此版本，并核对最终登录和选盘配置。
4. 已发布版本使用**查看**；需改动时点击**新版本**，编辑并发布后再为设备选择新版本。
5. 暂不用于新安装时点击**停用**，需要时**启用**；不再需要且无引用的草稿可删除。

## 4. 填写示例

| 项目 | 示例 |
| --- | --- |
| 名称 / OS | `Ubuntu-ARM64-NVMe` / 已启用的 Ubuntu Server ARM64 |
| 选盘 | 唯一匹配、仅 NVMe、序列号规则 `OS-*` |
| 分区 | EFI `1024` MiB、ext4 根分区留空使用剩余空间 |
| 登录 | 用户 `operator`、SSH 公钥登录、填写实际完整公钥 |
| 时区 / NTP | `Asia/Shanghai` / `192.0.2.123`（须替换为实际服务） |

本例须以相同架构的基础方案创建；如果 `OS-*` 匹配多块盘，在设备系统配置明确选择具体盘，再创建安装任务。

## 5. 注意事项

- 新方案继承基础方案的架构和网络模式，页面不能切换架构；缺少适用基础方案时先完成部署配置。
- 当前支持单盘 GPT / UEFI、EFI 与根分区，无 swap；页面不创建 RAID、LVM、多盘布局或自定义脚本。
- 无匹配、多个同等匹配或缺少容量时不会随意选盘；缩小规则或逐机指定盘。
- “继承所选方案”使用设备选择的具体方案版本；设备覆盖项以设备设置为准。
- 发布不执行安装；已创建任务保留原配置快照。密码登录时须在方案或设备补齐密码。
