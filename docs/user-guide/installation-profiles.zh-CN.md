# 安装方案

[English](installation-profiles.md) · **简体中文** · [页面使用指南](README.zh-CN.md)

## 1. 用途与入口

进入 **配置 → 安装方案**，统一设置一组服务器的 OS、选盘规则、分区及登录默认值。设备在**系统配置 → 当前安装方案**选择具体版本；逐机主机名、管理接口和固定地址在设备配置维护。

**新建方案**从内置 Ubuntu / UEFI 模板开始，空站点也可直接创建。选择 `x86_64` 或 `aarch64` 架构，无需先部署基础方案。**复制**以已有方案为起点，保留其架构和配置。

## 2. 字段填写

### 基本信息、磁盘及登录

| 字段 | 填写要求 |
| --- | --- |
| 方案名称 / 说明 | 名称必填，最多 100 字符；说明最多 1000 字符。 |
| 架构 | 从内置模板新建时选择 `x86_64` 或 `aarch64`；已有方案及其副本保留原架构。 |
| 默认 OS | 发布时须选择已登记、已启用且与方案架构相同的 Ubuntu Server OS。 |
| 选择规则 / 候选范围 | 唯一匹配、同规格多块取其一、容量最小或容量最大；范围为所有磁盘或仅 NVMe。“同规格多块取其一”用于一台设备有多块型号和容量都相同的候选盘：取序列号排序最靠前的一块，其余盘不使用；候选盘规格不一致时不选盘。设备明确指定盘时优先使用指定盘。 |
| 序列号 / 型号规则 | 可选；`*` 匹配任意字符，`?` 匹配单个字符，区分大小写；所有筛选条件同时生效。 |
| 最小 / 最大容量 | 可选，单位 GiB；容量规则需要完整的 Scout 容量信息，最小值不能大于最大值。 |
| 布局方式 | **直接分区**（默认）：根文件系统直接建在分区上。**LVM**：EFI 分区之后另建 `2048` MiB 的 `/boot` 分区，其余空间作为一个卷组，根文件系统建在逻辑卷上。 |
| 根分区格式 | `ext4` 或 `XFS`。 |
| EFI 分区 | 整数 `512–4096` MiB，默认 `1024`。 |
| 根分区 | 留空使用剩余空间；指定时至少 `20` GiB。直接分区时多余空间不分配；LVM 时多余空间留在卷组里，可用于以后扩容。 |
| 卷组名 / 根逻辑卷名 | 仅 LVM 使用，默认 `ubuntu-vg` / `ubuntu-lv`；以字母、数字或下划线开头，只含字母、数字和 `_ . + -`，最多 63 个字符。 |
| OS 用户名 | 普通用户，最多 32 字符；以小写字母或 `_` 开头，后续可用小写字母、数字、`_`、`-`，不能为 `root`。 |
| 登录方式 / 默认密码 | 选择 SSH 密码或公钥登录；密码可在方案或逐台设备配置，已有密码留空保留。**默认密码处理**可显式清除密码。 |
| SSH 公钥 | 每行一条完整公钥；公钥登录时最终配置须有有效公钥。 |

### 自定义文件

在**默认登录配置**下方点击**添加文件**，填写新系统中的绝对文件路径与内容。点击文件卡片可展开编辑；**文件属性**可设置所属用户/组、四位八进制权限，以及覆盖或追加，默认 `root:root`、`0644`、覆盖。空内容创建空文件；追加时需自行保留分隔换行，不会自动合并 YAML 或 JSON。

例如路径填写 `/etc/nico/site.yaml`，内容填写：

```yaml
nico_endpoint: "http://192.0.2.100:8080"
site: "site-a"
```

替换为实际地址后点击**发布版本**，为设备选择该版本。文件由新系统的 cloud-init 在首次启动、软件包和用户初始化后写入；父目录不存在时由 cloud-init 创建。普通重启不重复写入，方案修改不会更新已安装系统。安装后可使用 `sudo cat /etc/nico/site.yaml` 查看。

- 最多 32 个文件，单个正文最多 64 KiB，全部正文合计最多 256 KiB；UTF-8 原文保留缩进和换行。
- 文件路径不能重复或存在文件/目录冲突；系统网络、登录、cloud-init、运行时目录及安装回执等路径受保护，与基础模板的同路径文件也不能重复配置。
- 不替换 `${NICO_VIP}` 等变量，不下载远程文件，不执行写入的脚本；URL只作为正文保存。
- 自定义用户/组须已存在或由安装过程创建；目标镜像需支持 cloud-init 延迟写文件。写入失败会体现在既有主机配置验收的 cloud-init 错误中；手动跳过该验收不代表文件已写入。
- 此处用于普通文本配置，正文随方案保存并进入安装数据，不用于保管密码、私钥或令牌。

### 按需配置

展开**高级设置**填写：

| 字段 | 填写要求 |
| --- | --- |
| 时区 | IANA 时区，例如 `Asia/Shanghai`。 |
| NTP 服务器 | 可选，每行一个可达地址或主机名；留空时不通过 cloud-init 配置 NTP，也不验收 NTP 同步，不自动填入公共服务器。 |
| 额外软件包 | 每行一个包名；安装所需依赖须在 ISO 或配置的软件源中可用。 |
| APT 软件源 / 安全更新源 URL | 填写目标系统架构对应的可达源；离线安装留空时仅使用 ISO 材料。 |
| DNS 验收域名 / HTTP 验收 URL | 每行一项，在安装验收时检查服务；DNS 验收域名不是 DNS 服务器配置。 |
| Flat VPC ID / 租户 ID | 站点设置已初始化实例网络时，新建方案自动引用站点 Tenant 与 Flat VPC；否则可暂时留空。创建或发布方案本身不会创建资源，安装任务会核对 VPC 类型及所属租户。 |

## 3. 操作步骤

1. 点击**新建方案**，选择架构并填写名称，或**复制**已有方案。
2. 填写配置并点击**发布版本**，系统自动保存、检查并发布。缺少默认 OS、OS 用户名或材料不兼容时会分别提示；修正后再次发布，NTP 可留空。点击**关闭**不会保存未提交的编辑。
3. 发布后在设备**系统配置**选择此版本，并核对最终登录和选盘配置。
4. 已发布版本使用**查看**；需改动时点击**新版本**，编辑并发布后再为设备选择新版本。
5. 暂不用于新安装时点击**停用**，需要时**启用**；不再需要且无引用的草稿可删除。

## 4. 填写示例

| 项目 | 示例 |
| --- | --- |
| 名称 / OS | `Ubuntu-ARM64-NVMe` / 已启用的 Ubuntu Server ARM64 |
| 选盘 | 唯一匹配、仅 NVMe、序列号规则 `OS-*` |
| 分区 | EFI `1024` MiB、ext4 根分区留空使用剩余空间 |
| 登录 | 用户 `operator`、SSH 公钥登录、填写实际完整公钥 |
| 时区 / NTP | `Asia/Shanghai` / `192.0.2.123`（须替换为实际服务） |

点击**新建方案**，选择 `aarch64` 后填写本例配置。如果 `OS-*` 匹配多块盘，在设备系统配置明确选择具体盘，再创建安装任务；这些盘型号和容量都相同时，也可以把选择规则改为“同规格多块取其一”。

## 5. 注意事项

- 内置模板使用 Flat 网络模式；复制已有方案时保留其架构和配置，需要其他架构时另建方案。
- 当前支持单盘 GPT / UEFI、EFI 与根分区，无 swap；LVM 布局只创建一个卷组和一个根逻辑卷。页面不创建 RAID、多个逻辑卷、多盘布局或自定义脚本。
- 使用 LVM 时，如果其他磁盘上已有同名卷组，安装会在写盘前停止；请改用其他卷组名，或先处理那块磁盘。
- 无匹配、多个同等匹配或缺少容量时不会随意选盘；缩小规则或逐机指定盘。
- “继承所选方案”使用设备选择的具体方案版本；设备覆盖项以设备设置为准。
- 发布不执行安装；已创建任务保留原配置快照。密码登录时须在方案或设备补齐密码。

### 安装验收项目

安装验收文案统一为：安装器成功 → 主机配置 → 系统盘与 EFI 分区验证 → 网络配置 → SSH 连通 → DNS / HTTP / NTP 连通 → 重启验收。“系统盘与 EFI 分区验证”核对 root 和 ESP 位于目标盘（LVM 布局同时核对卷组、逻辑卷和 `/boot`），不表示再次修改固件启动顺序。仅检查已配置的 DNS/HTTP 验收目标和 NTP；已配置服务的必选/告警策略不变。
