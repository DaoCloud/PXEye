# 设备管理

[English](device-management.md) · **简体中文** · [页面使用指南](README.zh-CN.md)

## 1. 用途与入口

进入 **资源 → 设备管理**，提前导入到货规划，发现并纳管设备，再将规划应用到对应服务器的配置。

| TAB | 用途 |
| --- | --- |
| 发现设备 | 查看 DHCP 端点，使用 BMC / PMC 凭据获取身份，再加入纳管设备。 |
| 纳管设备 | 查看已有设备，使用一键匹配、系统配置及地址管理；默认打开此 TAB。 |
| 设备规划 | 导入或编辑 SN、地址、MAC、管理子网和机柜，与纳管设备的配置对比。 |

七字段到货规划独立保存。导入后继续按原来的发现、认证及纳管步骤操作，规划不会自动成为纳管设备。五字段网卡规划的保存规则见第6节。

设备规划位于最后一个 TAB，可按 SN、IP、MAC 或机柜搜索。

## 2. 字段填写

### 到货规划

在**设备规划**下载 CSV 模板，每行一台主机，也可点击**新增规划**逐台填写。

| CSV 字段 | 页面字段 | 填写要求 |
| --- | --- | --- |
| `serial` | 设备 SN | 必填且唯一；匹配时与纳管设备序列号完全一致。 |
| `management_ip` | 管理 IP | 规划的主机管理 IPv4；填写时必须提供管理 MAC。 |
| `management_mac` | 管理 MAC | 实际主机管理/启动接口的 MAC；即使管理 IP 和子网留空，匹配也会指定此接口。 |
| `management_subnet` | 管理子网 | CIDR，例如 `192.0.2.0/24`；填写时必须提供管理 MAC。 |
| `bmc_ip` | BMC IP | 规划的 BMC IPv4；不是当前发现所用的临时地址。 |
| `bmc_mac` | BMC MAC | 填写时须与已纳管设备的 BMC MAC 一致。 |
| `rack` | 机柜 | 用于规划展示和对比，一键匹配不修改设备机柜归属。 |

CSV 必须包含这七列表头；除 SN 外可留空。更新已有规划时，CSV 空单元格保留原值；需要清空时使用**编辑规划**。管理子网只显示范围，不显示名称。

### 服务器系统配置

在**纳管设备**点击服务器的**系统配置**：

| 字段 | 填写要求 |
| --- | --- |
| 设备名称 / 机柜 ID | 名称用于展示；机柜填写实际 NICo Rack ID，不是 CSV 中的机柜展示名称。 |
| BMC 用户名 / 密码 | 使用有效控制器凭据；已有密码留空保留，与 OS 登录凭据分别维护。 |
| BMC 规划 IP / 地址策略 / 子网 | 按实际规划填写；固定地址须在对应子网内，保存后通过独立操作更新 BMC。 |
| 启动网卡 MAC / 管理 IP / 管理子网 | 选择真实 PXE / OS 管理口；子网选已有 HostInband 范围。 |
| 主机名 | 1–63 个小写字母、数字或 `-`，首尾须为字母或数字，例如 `gpu-01`。 |
| 当前安装方案 | 选择已发布且启用的[安装方案](installation-profiles.zh-CN.md)具体版本。 |
| 下次安装系统盘 | 首次安装可使用方案规则，重装可沿用当前盘；也可从已采集磁盘中指定盘。 |
| 设备覆盖设置 | OS、用户名、登录方式、密码和公钥可继承所选方案或逐机设置；继承密码时不显示设备密码框。OS 密码为 8–128 字符，不含换行；公钥每行一条完整公钥。 |

### 交换机与供电框配置

| 字段 | 填写要求 |
| --- | --- |
| 设备 SN / 名称 | SN 用于唯一识别，已登记 SN 只读；名称用于展示。 |
| BMC / PMC MAC、目标 IPv4、管理网络 | 填写真实接口及规划地址，选择已有 Underlay 子网。 |
| BMC / PMC 用户名、密码、保留凭据 | 使用有效凭据；密码留空保留，凭据处理按设备与站点策略选择。 |
| 机柜 UUID | 可选，填写真实 NICo Rack UUID。 |
| NVOS 管理接口 | 仅交换机填写：接口 MAC 及 Underlay 子网；目标 NVOS IPv4 只支持单管理口，NVOS 凭据按需提供。 |
| 说明与标签 | 可选；标签使用 JSON 数组，例如 `["rack-a"]`。 |

### 接口地址规划

在**地址管理 → 规划地址**核对接口 MAC、当前 IPv4 和管理子网，填写**规划 IPv4**。BMC / PMC 接口可保存自己的账号密码，已有密码留空保留；设备名称、类型和接口角色用于识别该端点。

## 3. 操作步骤

### 导入与编辑

1. 在**设备规划**点击**下载模板**，填写 CSV，点击**导入规划**。
2. 点击**校验并预览**，核对新增、更新、无变化及格式错误；修正错误后重新预览。
3. 点击**保存导入规划**。之后可使用**编辑规划**修改各行；已有硬件关联网卡规划的记录不能修改 SN。

纳管列表的**导入设备 / 下载模板**先选择类型：服务器使用相同的设备规划 CSV；交换机和供电框使用各自模板，嵌套字段填 JSON，预览后点击**确认保存本地规划**。**新增设备**可按类型逐台填写。非服务器本地规划需独立点击**同步至 NICo**，核对声明和影响、输入 SN 并确认接入；同步可能启动原生设备管理及凭据处理。

### 发现与纳管

1. 确认设备启用 DHCP，且到 NICo 的请求与应答路径可达。
2. 在**发现设备**找到端点，点击**获取设备信息**，填写有效 BMC / PMC 账号密码。
3. 多台设备共用账号密码时，勾选端点（也可全选当前筛选列表），点击**批量获取设备信息**，弹窗仅填写共用账号和密码，直接使用已选设备的当前管理地址，无需重复查看设备列表或选择地址；每批最多50台，同时读取最多4台。切换发现子网会清空选择，归属冲突或缺少可用管理 IPv4 的端点不可选择。
4. 查看逐台 SN、设备类型、型号和成功/失败结果。成功信息保留在当前页面，可从**查看获取结果**重新打开；失败设备用正确账号另选一批，其他设备不受影响。
5. 点击**确认并纳管**或列表中的**确认设备信息**，核对后点击**加入纳管设备**。批量结果中可逐台确认，成功设备无需重复输入密码；纳管清单沿用识别类型。

获取信息只读取已发现端点，不会自动纳管或修改硬件。密码不保存到浏览器状态或结果中；服务端沿用受限身份验证记录支持后续纳管。验证有效期为15分钟；刷新整个页面、地址/归属变化或验证失效后须重新获取。

发现时获取信息与纳管后的**刷新设备详情**使用相同的识别规则，支持物理服务器、NVLink 交换机及受支持的供电框。刷新同时核对设备 SN 和管理 MAC；身份或类型冲突时提示失败。

### 一键匹配

1. 在[网络管理](network-management.zh-CN.md)创建与规划 CIDR 完全一致的 HostInband 子网，并配置实际网关。
2. 在**纳管设备**勾选服务器，点击**一键匹配**；每次最多50台。
3. 查看逐台结果。系统按唯一 SN 关联规划，核对管理 MAC 的硬件归属，再保存 BMC 目标地址、管理接口及子网配置。
4. BMC 地址使用**更新 BMC 地址**执行；主机管理配置由安装任务应用。安装方案和 OS 账户在**系统配置**维护。

规划页的“配置一致”表示规划与保存的设备配置一致；修改源规划后，需要再次点击一键匹配。

### 保存配置与更新地址

1. 在**系统配置**填写服务器配置，点击**保存规划**；地址也可通过**地址管理 → 规划地址 → 保存规划**维护。保存后不会立即安装或改址。
2. 需要更新 BMC / PMC 时，在纳管列表勾选设备，点击**更新 BMC 地址**，阅读影响并点击**确认并开始更新**。
3. 查看**检查地址与身份 → 更新 BMC → 验证新地址 → 同步管理记录**四步进度。合格设备通过 Redfish 关闭 DHCP 并写入规划静态地址；不合格设备显示原因。
4. 已提交的任务关闭弹窗后继续执行，可从近期更新记录重新查看；遇到错误按界面使用**重新检查并更新**或**核对并完成同步**。
5. 服务器主机管理地址及系统配置通过[安装任务](installation-tasks.zh-CN.md)应用；**更新管理地址**只提供受支持接口的 Redfish 预检，不能替代主机 OS 网络配置。

双击设备行或点击设备名称查看详情。在纳管列表勾选设备点击**刷新设备详情**，页面提示后台任务已启动，完成后再查看硬件更新时间和结果。

## 4. 填写示例

以下为虚构数据，到现场须替换为实际规划：

```csv
serial,management_ip,management_mac,management_subnet,bmc_ip,bmc_mac,rack
SERIAL-1,192.0.2.10,02:00:00:00:00:21,192.0.2.0/24,198.51.100.10,02:00:00:00:00:20,RACK-01
```

纳管 SN 为 `SERIAL-1` 的服务器后，一键匹配会将 `02:00:00:00:00:21` 设置为管理/启动口，并关联已有 `192.0.2.0/24` 子网；掩码和网关从该子网读取。

## 5. 注意事项

- **匹配条件**：只支持服务器 SN 唯一匹配；管理 MAC 必须在已采集硬件中存在，子网须精确且唯一匹配。缺少硬件信息时先获取设备详情。
- **凭据与生效**：匹配保留已有 BMC 和 OS 凭据，不发起 Redfish 改址、DHCP 分配、重启或安装。
- **异常与并发**：失败设备不保存，其他合格设备可继续；规划或设备配置已变化时刷新后再匹配，已有地址操作须先完成。
- **格式**：服务器规划 CSV 最大1 MiB、最多5000行；交换机/供电框类型模板最大2 MiB。旧版 Expected Machine CSV/Excel 使用不同格式，须按所选入口下载模板。
- **其他设备**：交换机及供电框使用各自的系统配置和地址管理；不创建服务器 OS 安装任务。仅有 DHCP 地址的未知端点可先维护地址规划，不能因此视为已验证、可装机的服务器。

## 6. 导出并导入网卡地址规划

1. 在**发现设备**获取服务器信息后，选中服务器并点击**导出网卡规划表**；也可在**纳管设备**中选中服务器导出，每次1–50台。
2. 表格已包含主机序列号和已采集主机网口 MAC，填写 `ip`、`subnet`（CIDR）和 `gateway`。不使用的网口后三列留空；空白不会删除已有配置。
3. 使用原**导入设备 → 服务器**或**导入规划**，上传 CSV、核对预览并保存。无需填写子网 ID、掩码或 NICo JSON。
4. 已纳管服务器直接保存到**系统配置**；未纳管服务器先保存源规划，确认纳管时按 SN/MAC 自动带入。带入失败会提示，可核对后使用原**一键匹配**重做。
5. 确认原主启动接口、安装方案等配置，按原流程安装。Ubuntu 安装器按 MAC 配置多个静态接口，首启和重启验收检查其地址、前缀和 MTU。

```csv
serial,mac,ip,subnet,gateway
SERVER001,02:00:00:00:01:01,192.0.2.11,192.0.2.0/24,192.0.2.1
SERVER001,02:00:00:00:01:02,198.51.100.11,198.51.100.0/24,
```

示例为文档地址。每行一个网口，SN可重复，MAC/IP不可重复。单次最多5000行、1 MiB。
子网须精确对应网络管理中已有的单IPv4前缀HostInband，网关与子网定义一致；没有网关的子网可留空。
导入保留凭据和主启动接口；没有启动口的机器仍需在系统配置明确选择，不按表格顺序猜测。
预览15分钟有效；设备/硬件/源规划/网络变化、IP冲突或活动任务都会阻止保存，不部分导入。

**路由与生效**：默认路由只使用原管理口。附加网口继承子网MTU，网关会保存，但不自动生成额外默认路由或推断跨网段目标路由。
保存不修改正在运行的OS、BMC或交换机；下次安装时生效。源规划与系统配置不同时显示差异。
本功能仅处理已采集主机以太网MAC；不包含BMC/DPU管理口、IB、Bond、VLAN、IPv6或策略路由。
BMC未回报全部网口时，先用现有硬件读取入口补齐Scout信息；导出不自动启动Scout或重启机器。
