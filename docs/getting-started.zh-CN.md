# 首台装机

[English](getting-started.md) · **简体中文** · [文档中心](README.zh-CN.md)

本文以一台服务器为例，从纳管走到 OS 验收。先完成[服务部署](deployment.zh-CN.md)，选择专用设备，在发现和写入 OS 的对应阶段完成[装机前检查](pre-installation-checklist.zh-CN.md)，验证该硬件流程后再扩大批次。

## 1. 核对站点和网络

网络页面的字段填写和操作步骤见[网络管理使用指南](user-guide/network-management.zh-CN.md)。

打开**站点设置**，查看 Core 连接、客户端身份和存储。在**网络管理**核对 BMC 发现网段及主机引导/管理网段。relay 和路由在 PXEye 之外配置。

只有 BMC 已启用 DHCP、请求能够到达 NICo，才能通过 DHCP 发现未知 BMC 地址。未知静态地址需要先通过现场网络或清单流程解决。

## 2. 准备操作系统

在**操作系统**上传受支持的 Ubuntu ISO，或从配置的来源目录导入。目录路径属于 PXEye 服务运行环境。等待材料提取和发布检查完成，登记到 NICo，再确认可以选择该 OS。

自己的 ISO 替代目标安装材料，不替代 Scout 发现环境。目标机器需要访问 ISO、kernel、initrd 和安装元数据 URL。

## 3. 发现并纳管设备

进入**设备管理 → 发现设备**，选择 BMC 来源网络并刷新。提供控制器凭据，点击**获取设备信息**。按照序列号和设备类型核对到货硬件，再选择纳管。

已有到货清单在**设备管理 → 设备规划**使用 CSV 模板导入。规划独立保存，设备仍按上述步骤发现并纳管；之后在纳管设备中点击**一键匹配**应用地址和管理子网配置。格式见[设备管理指南](user-guide/device-management.zh-CN.md)。

## 4. 保存地址与安装配置

在**纳管设备**按控制器或接口 MAC 编辑地址规划，分别核对当前与规划 BMC 地址。服务器通过**系统配置**设置 hostname、目标 OS、账号和安装方案。

在**安装方案**创建通用配置，选择适合整批机器的磁盘规则和分区策略。规则结合硬件回报解析到目标盘，不依赖猜测的 `/dev/sdX` 名称。适用字段由设备显式配置覆盖方案默认值。

保存与执行分开。如果安装前需要更改 BMC 地址，选中设备并执行**更新 BMC 地址**，流程包含身份检查、控制器改址、新地址验证和记录同步。迁移过程中保留对当前管理网络的访问。

交换机、DPU 端点和供电设备只走纳管及地址管理，不创建服务器 OS 安装任务。

## 5. 创建安装任务

打开**安装任务**，选择服务器并新建任务。流程自动判断分配还是复用 Instance。确认前核对实际 OS、地址、hostname、系统盘选择和接入清理范围。

首次接入时，NICo 可能启动 Scout 并执行站点硬件准备策略。接入清理可能涉及全部磁盘，独立于 OS 系统盘选择；应对目标设备确认这个范围。

## 6. 跟踪执行与验收

任务页提供 BMC 控制台链接和持久日志。依次观察准备、安装、系统盘引导、SSH 验证和普通重启验证。完成需要验收证据，不能仅凭安装器登录界面判断成功。

遇到“需处理”，先查看具体错误、日志和真实主机状态，再使用明确范围的恢复入口。编辑设备规划不会改变已冻结任务；恢复动作会说明使用哪份配置。

## 7. 保存交付记录

验收报告可用后下载，随数据卷保留任务、实际规划、日志和回执。Instance release 是独立回收流程，可能清理设备，不是删除安装历史。
