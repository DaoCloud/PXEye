# 交互规则

[English](interaction-rules.md) · **简体中文** · [设计文档](README.zh-CN.md)

新增或修改页面时遵守的规则。它们是从现有页面归纳出来的现行做法；第 2 节里“没有值的列不显示”和“没有内容时说明适用范围”两条，以及第 6 节，是随设备运行状态页面新定的，早先的页面还没有全部做到。与某个页面的现状冲突时，先确认是页面该改还是规则该改，不要各写各的。

## 1. 页面归属

每份数据只有一个维护入口。其他页面引用它、跳转到它，不另做一个编辑入口。

| 导航 | 页面 | 拥有的数据和操作 |
| --- | --- | --- |
| 总览 | 机柜拓扑 | 按机柜查看设备；人工排列顺序 |
| 装机 | 安装任务 | 选择设备、检查、确认、执行、日志和验收 |
| 资源 | 设备管理 | 设备规划、发现、纳管、地址、机柜归属、逐机安装配置 |
| 资源 | 设备管理 → 服务器 / 交换机 / 供电框 | 只读：NICo 回报的运行状态。不拥有任何可编辑数据 |
| 资源 | 实例管理 | 实例查看和回收 |
| 资源 | 操作系统 | ISO、启动材料、OS 定义 |
| 资源 | 网络管理 | 网段、地址范围、网络服务 |
| 配置 | 安装方案 | 可复用的 OS、磁盘、分区和登录默认值 |
| 配置 | 站点设置 | Core 连接、站点发现、凭据、并发 |
| 配置 | NICo 集群 | 控制面部署和状态 |

- 新页面先判断属于哪一组；能放进现有页面的页签或弹窗，就不新开菜单。
- 从属于某个页面的视图做成它的二级菜单，不与它并列。
- 只读视图需要编辑时，打开数据所属页面的现有弹窗。

## 2. 页面结构

- 页面顶部是标题、一句话说明和操作按钮。说明写这个页面用来做什么，不写实现方式。
- 列表用表格，详情和编辑用弹窗，多步操作用向导。
- 一个操作区域只有一个主按钮。
- 筛选区在表格上方；筛选和搜索不清除已有选择，搜索输入时保持光标位置。
- 所有行都没有值的列不显示。
- 页面在当前站点没有内容时，说明它的适用范围和下一步去哪里，不显示空表。
- 复杂的原始状态、接口返回和日志放在详情里；主内容只放设备、范围、阶段、原因和处理入口。

## 3. 文案

- 页面按功能描述，字段按输入内容描述，提示按结果和下一步描述。
- 标签用简短名词，按钮用明确动作。
- 术语全站统一：主机名、管理地址、BMC 地址、机柜、供电框、安装方案。产品里叫“机柜”，对应 NICo 的 Rack；字段名和原生资源名保持 `rack_id`、`Rack` 不翻译。
- MAC、CIDR、UUID、资源 ID 和状态机的状态名原样显示，不翻译成别的概念。
- 输入格式、单位、留空的含义写在字段旁边。
- 数量归入计数，查询时间靠近查询结果，失败原因靠近失败的那一条。
- 删除重复的流程说明、和按钮重复的长提示、没有实际结果的状态说明。

## 4. 状态和证据

- 用颜色加文字表达状态，不只靠颜色。绿色表示正常或已完成，琥珀色表示需要关注或进行中，红色表示失败，灰色表示未知或未开始。
- 没有数据不等于正常。没有收到报告显示“未报告”，不显示成健康或在线。
- 区分三种信息：人填写的期望值、系统读回的实际值、NICo 状态机回报的状态。它们分开显示，不互相替代。
- 状态名不能直接当作结论。是否需要处理，用系统自己给出的信号（处理失败、超出时限、健康告警），不按状态名字猜。
- 读回的信息标明来源和时间。
- 一类数据读取失败时说明是哪一类，其余照常显示。
- 请求已接受不等于操作完成；已登记不等于已就绪；端口可达不等于验收通过。

## 5. 危险操作

- 会改变设备或共享资源的操作，确认时写明对象和影响：覆盖哪块系统盘、是否清理全部磁盘、是否重启、改哪个地址、回收哪个实例。
- 精简文字不能减少必要的确认、校验或后台检查。
- 外部写入先记录是否已发出。结果未知时先读回，不自动重发。
- 失败后保留现场和原因，给出明确的恢复入口；不提供做不到的一键取消或一键重试。
- 批量操作逐台显示结果，一台失败不改变其他设备的结果。

## 6. 只读和预览功能

- 只读视图不发起写请求。能点的操作只有刷新、筛选，以及打开其他页面已有的入口。
- 预览功能由站点开关控制。关闭时导航、接口和现有页面的行为与没有这个功能时一致。
- 只读观察实例在页面上有常驻标识，写请求由后端统一拒绝，不靠隐藏按钮。

## 7. 视觉和可访问性

- 沿用现有组件：页面标题、表格、状态标签、定义列表、提示框、弹窗、筛选区、汇总条。不为单个页面引入新的颜色或组件。
- 标识、MAC、IP、ID 用等宽字体。
- 弹窗打开时背景不可操作，焦点进入弹窗并限制在弹窗内；动态结果用实时通知区域播报，错误用警告语义。
- 窄屏时表单变为单列，表格在自己的区域内横向滚动，页面本身不出现横向滚动条。
- 尊重系统的“减少动画”设置。

## 8. 新页面检查清单

1. 数据的维护入口是哪个页面？本页面是拥有它还是引用它？
2. 每一列、每一项在真实站点上有没有值？没有值的怎么处理？
3. 用户来到这个页面能做的第一件事是什么？
4. 状态用的是系统的信号，还是自己对状态名的解读？
5. 有没有写操作？有的话对象、影响和确认方式是什么？
6. 开关关闭时，现有页面是否完全不受影响？
7. 文案是否沿用了现有术语？
8. 属于机柜运维的功能，是否更新了[能力需求](rack-operations-requirements.zh-CN.md)里对应功能域的实现状态？
