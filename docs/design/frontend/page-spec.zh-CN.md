## 运维 › 机柜管理

机柜是默认的操作单位。本页回答每个机柜处在流程的哪一步、有没有需要处理的问题。

- 入口：运维 → 机柜管理（默认首页）
- 设计章节：5 整体操作运维流程；6.3 机柜与设备
- 现有页面：设备管理 → 机柜（列与状态用词沿用）；机柜拓扑的统计条并入
- 脚本：`pages/racks.js`，路由 `#racks`

### 功能点

| 编号 | 功能点 | 类型 | 说明 |
| --- | --- | --- | --- |
| 1 | 统计条 | 调整 | 机柜数、就绪数、需要处理、设备就绪、进行中的任务。取代机柜拓扑页的设备数量统计。 |
| 2 | 机柜表 | 调整 | 机柜、NICo 状态、健康、机柜规格、成员设备沿用现有机柜页；列表同时包含清单里还没有 NICo 对象的机柜。点击整行进入机柜详情。 |
| 3 | NICo 状态 | 沿用 | 显示状态机的状态原文和进入时间，不翻译、不另起状态名。还没有 NICo 对象的机柜显示“尚未建立”。 |

| NICo 状态 | NICo Core | Discovering、Maintenance（带阶段）、Validating、Ready、Error、Deleting；没有对象时为“尚未建立” |

- “需要处理”只用 NICo 的信号：状态为 Error、有整柜泄漏、成员设备有严重告警。
- 清单里的机柜都出现在这里，不论 NICo 里有没有对象。

- 入口：运维 → 机柜管理，点击整行；设备管理、设备清单、健康告警、NVLink 域管理、运维任务页里的机柜链接

- 脚本：`pages/rack.js`，路由 `#rack`

### 功能点

| 编号 | 功能点 | 类型 | 说明 |

| 4 | 页签 | 新增 | 清单核对、设备、任务、健康与历史。已就绪的机柜默认打开设备，其余默认打开清单核对。 |

| 8 | 设备表 | 沿用 | 设备 / 序列号、BMC 地址、运行状态、健康、电源沿用服务器页；行操作“运行状态”“操作”不变。 |

### 字段

| 字段 | 来源 | 说明 |
| --- | --- | --- |
| 成员电源 | 各成员设备的电源状态 | 全部开机、全部关机，或“N / M 开机” |
| NICo 上线进度 | NICo 机柜状态 | 状态里带着所在的阶段 |
| 实测槽位 | NICo，经硬件后端从设备读到 | 和清单里写的槽位比对 |
| 对上线的影响 | NICo 机柜规格 | 交换机未到齐时上线不会开始；计算托盘和供电框缺件、槽位不一致都不影响 |
| 固件 | 设备实际版本对比推荐基线 | 与基线相同 / 与基线不同；供电框没有可读的版本 |

### 规则与门控

- 确认接入之前，平台只读设备，不写 NICo；NICo 不会接管这个机柜的任何设备，也就不会开始上线。
- 确认接入之后，上线由 NICo 的机柜状态机自动进行：就绪的交换机数达到机柜规格里写的数量后开始。NICo 没有“等人确认再开始”的开关，阶段的顺序也不能调整，开始后不能在页面上取消。
- 交换机的数量门槛写在 NICo 的机柜规格里，只有管理员修改站点配置才能改。
- 机柜进入 Error 后不会自己恢复；原因消除后要“重新执行机柜维护”。
- 清单核对帮人在确认接入前看清差异；确认接入之后它不拦截上线。
- 同一机柜同时只有一个任务，执行期间其他机柜级操作禁用。
- 有整柜泄漏的机柜：NICo 自动强制下电，并拒绝上电。
- 机柜上还有实例时不能退役。
- 下电、重启和有实例时的固件更新是高风险操作，要输入机柜 ID。
- 待定：上线期间计算托盘是否需要由平台放行，实测后确定。

- NICo 没有启用 NVLink 分区时，分区表为空。

### 规则与门控

- 读取身份和匹配只读设备，不写 NICo。机柜确认接入之前，NICo 不会接管这个机柜的任何设备。
- 匹配只按序列号，不按地址或位置猜测。
- 读取身份只用这台设备在清单里对应的凭据或批次默认凭据，失败后不再尝试其他口令，交给人指定。
- 清单里没有的设备不会写进 NICo。
- “替换清单中的一行”会产生新的清单版本，并写入审计。
- 忽略的端点不再显示；它再次申请地址时会重新出现。

## 配置 › 站点设置 › 站点概况

回答“平台现在能不能用”。把控制面、硬件后端和设施接入的就绪状态放在一页，并说明缺失时哪些操作受影响；同时把 NICo 在各种情况下会怎么做摆出来。
