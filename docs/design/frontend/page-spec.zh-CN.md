[设计稿说明](README.zh-CN.md) · [设计文档](../README.zh-CN.md)

本文件由 `tools/build-spec.mjs` 从页面脚本生成，不要直接修改。页面与说明写在同一个文件里，改页面时一起改。

## 运维 › 机柜管理

机柜是默认的操作单位。本页回答每个机柜处在流程的哪一步、有没有需要处理的问题。

- 入口：运维 → 机柜管理（默认首页）
- 设计章节：5 整体操作运维流程；6.3 机柜与设备
- 现有页面：设备管理 → 机柜（列与状态用词沿用）；机柜拓扑的统计条并入
- 脚本：`pages/racks.js`，路由 `#racks`

### 功能点

| 编号 | 功能点 | 类型 | 说明 |
| --- | --- | --- | --- |
| 1 | 统计条 | 调整 | 机柜数、就绪数、需要处理、设备就绪、进行中的任务。取代机柜拓扑页的设备数量统计。 |
| 2 | 机柜表 | 沿用 | 机柜、NICo 状态、健康、机柜规格、成员设备沿用现有机柜页；点击整行进入机柜详情。 |
| 3 | NICo 状态 | 沿用 | 显示状态机的状态原文和进入时间，不翻译、不另起状态名。 |
| 4 | 对账 | 新增 | 等待发现、N 项阻塞、有差异不阻塞、无阻塞项。阻塞项清零前不能上线。 |
| 5 | 当前任务 | 新增 | 显示正在执行的 Flow 任务及其阶段。同一机柜同时只有一个任务。 |

### 字段

| 字段 | 来源 | 说明 |
| --- | --- | --- |
| NICo 状态 | NICo Core | Created、Discovering、Maintenance、Validating、Ready、Error、Deleting |
| 机柜规格 / NVLink 域 | NICo Core | 规格由清单推导；NVLink 域对应 NICo 的机柜组 |
| 成员设备 | 期望清单 + NICo | 三类设备的数量与就绪数 |
| 实例 | NICo Core | 机柜上已交付的实例数 |

### 规则与门控

- “需要处理”只用 NICo 的信号：对账阻塞、状态为 Error、有阻止分配的告警。
- 没有期望清单的机柜不出现。

## 运维 › 机柜管理 › 机柜详情

一个机柜的工作台：看它在流程的哪一步，处理对账问题，发起机柜级操作并跟踪任务。

- 入口：运维 → 机柜管理，点击整行；设备管理、设备清单、健康告警、NVLink 域管理、运维任务页里的机柜链接
- 设计章节：5 整体操作运维流程；6.3 机柜与设备；9 操作设计
- 现有页面：设备管理 → 机柜的详情弹窗（状态、健康、成员、状态历史）扩展为页面；发现诊断、布线并入“对账”；机柜拓扑并入“设备”页签
- 脚本：`pages/rack.js`，路由 `#rack`

### 功能点

| 编号 | 功能点 | 类型 | 说明 |
| --- | --- | --- | --- |
| 1 | 机柜概况 | 调整 | NICo 状态、健康、电源、固件基线、实例数。沿用机柜详情弹窗的字段。 |
| 2 | 机柜操作 | 调整 | 上线、电源、固件更新、期望与实际校验、退役。不可用时按钮禁用并在提示里写明原因；机柜就绪后不再显示“开始上线”。现有的“机柜维护”弹窗被拆成这几个单一动作。 |
| 3 | 流程位置 | 新增 | 接入与对账、机柜上线、可交付三步，标出当前位置和每步的完成情况。 |
| 4 | 页签 | 新增 | 对账、设备、任务、健康与历史。已就绪的机柜默认打开设备，其余默认打开对账。 |
| 5 | 对账统计 | 新增 | 三类设备的就绪数和阻塞项数。交换机就绪数达到机柜规格要求才能上线。 |
| 6 | 对账问题 | 调整 | 把发现诊断（探测失败、错误码、处理建议）、布线（接线不符）和清单比对（序列号不符、未发现）合成一张表，每行一个处理入口。 |
| 7 | 机柜立面 | 调整 | 取代机柜拓扑的卡片视图：按槽位从上到下排列，颜色表示健康，点击打开设备的运行状态。 |
| 8 | 设备表 | 沿用 | 设备 / 序列号、BMC 地址、运行状态、健康、电源沿用服务器页；行操作“运行状态”“操作”不变。 |
| 9 | 任务卡 | 新增 | 按阶段显示 Flow 任务的进度和每个阶段的结果；执行中的任务可以取消。 |
| 10 | 状态历史 | 沿用 | 沿用机柜详情弹窗的状态历史（状态、进入时间、停留）和当前健康告警。 |

### 字段

| 字段 | 来源 | 说明 |
| --- | --- | --- |
| 对账问题 · 影响 | NICo 机柜规格 | 阻塞上线：序列号不符、交换机未发现；不阻塞：供电框或计算托盘缺失、接线不符 |
| 固件 | 托盘实际版本对比推荐基线 | 符合基线 / 偏差 |
| 电源 | NICo 读回 | On / Off / 未报告 |

### 规则与门控

- “上线”对应 NICo 的 bringup：固件、NVOS、NMX-C 配置和机柜校验。
- 同一机柜同时只有一个任务，执行期间其他机柜级操作禁用。
- 对账有阻塞项、机柜未发现或已 Ready 时不能开始上线。
- 有泄漏告警的机柜拒绝上电。
- 机柜上还有实例时不能退役。
- 下电、重启和有实例时的固件更新是高风险操作，要输入机柜 ID。

### 弹窗：操作确认（上线、电源、固件更新、退役共用）

只显示对象、动作、受影响的实例、将经过的阶段。

| 输入 | 必填 | 说明 |
| --- | --- | --- |
| 固件基线 | 仅固件更新 | 只能选择基线 |
| 原因 | 是 | 写入任务和审计 |
| 输入机柜 ID | 高风险时 | 下电、重启、有实例的固件更新、退役 |

### 弹窗：更换设备

从“序列号不符”的对账问题进入，按实物更新期望清单。

| 输入 | 必填 | 说明 |
| --- | --- | --- |
| 新序列号 | 是 | 默认带入实测值 |

## 运维 › NVLink 域管理

NVLink 域是固件一致性和交付门控的单位。本页用来发现域内版本不一致，并以域为单位发起更新。

- 入口：运维 → NVLink 域管理
- 设计章节：6.3 机柜与设备；10 非功能设计（固件一致性、分阶段发布）
- 现有页面：新增页面。现有交换机详情里的“NVLink 域”字段是它的来源
- 脚本：`pages/racks.js`，路由 `#domains`

### 功能点

| 编号 | 功能点 | 类型 | 说明 |
| --- | --- | --- | --- |
| 1 | 域列表 | 新增 | 域、拓扑、成员机柜、域状态、健康和实例数。机柜可点击进入详情。 |
| 2 | 固件基线一致性 | 新增 | 域内各机柜的固件基线是否一致。不一致时列出各基线。 |
| 3 | 域级操作 | 新增 | 域级固件更新和域级电源。域内任一机柜不满足门控时不可用，并说明原因。 |
| 4 | 分阶段发布记录 | 新增 | 每次域级固件更新的批次和状态。对应 Flow 的分阶段发布。 |

### 字段

| 字段 | 来源 | 说明 |
| --- | --- | --- |
| 域状态 | NICo + NMX-C | 已形成 / 未报告 |
| 固件基线 | 各机柜实际基线的汇总 | 一致 / 不一致 |
| 批次 | Flow 分阶段发布 | 每批一个机柜，前一批成功后才开始下一批 |

### 规则与门控

- 域级固件更新是高风险操作，要输入域 ID 确认，并显示域内全部实例数。
- 任一批失败后停止后续批次，已完成的机柜不回滚。

| 原因 | 是 |  |
| 输入域 ID | 是 | 高风险确认 |

## 配置 › 安装方案

可复用的系统安装配置。合并现有的操作系统材料和安装方案，交付时只需选一个方案。

- 入口：配置 → 安装方案
- 设计章节：6.6 档案与审计
- 现有页面：安装方案页（表头、状态、行操作沿用）与操作系统页（ISO 与 OS 版本）合并
- 脚本：`pages/profiles.js`，路由 `#os-templates`

### 功能点

| 编号 | 功能点 | 类型 | 说明 |
| --- | --- | --- | --- |
| 1 | 方案列表 | 沿用 | 名称 / 版本、默认系统 / 安装器、分区 / 默认登录配置、状态 / 引用、操作，与安装方案页一致。 |
| 2 | 状态 / 引用 | 沿用 | 草稿、已发布、已停用。已发布的版本只读，修改要建新版本。 |
| 3 | 不做逐机配置 | 调整 | 去掉设备覆盖设置和逐机网卡规划：整机柜的托盘同质，主机名和地址来自清单。 |

### 规则与门控

- 新建和发布方案需要管理角色。
- 交付只能选择已发布的方案。
- 编辑弹窗沿用安装方案的基本信息、系统盘选择、分区布局、默认登录配置、安装验收。
