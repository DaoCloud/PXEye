## 运维 › 机柜管理 › 机柜详情

- 入口：运维 → 机柜管理，点击整行；设备管理、设备清单、健康告警、NVLink 域管理、运维任务页里的机柜链接

### 规则与门控

- 一个新机柜要人点头的地方依次是：设备发现里纳管（逐台或批量）、设备管理里一键匹配、这一页登记机柜、这一页开始上线、安装任务里装系统。前两步和现有产品一样，登记机柜和开始上线是整柜新增的。
- 机柜页只放机柜对象上的操作。纳管是逐台设备的事，在设备发现里做；装系统和实例只在单台机器上。
- 登记机柜只带上已纳管并且已经一键匹配的成员：没有匹配的设备，机柜和槽位还没有写进它的配置。之后才纳管、匹配的成员自动补进这个机柜。
- 登记机柜之前，交换机和供电框只在平台本地纳管，NICo 不知道它们；计算托盘的声明在纳管时已写入 NICo，带暂停标记，NICo 不给它上电，也不接管。
- 开始上线提交的是一个上线任务：供电框上电、计算托盘上电并放行接管、计算托盘固件、交换机上电、核对交换机固件、计算托盘重启。
- 交换机就绪数达到机柜规格里写的数量后，NICo 的机柜状态机自动开始机柜维护。这一段没有“等人确认”的开关，阶段的顺序不能调整。进行中可以终止，终止后机柜进入 Error。
- 交换机的数量门槛写在机柜规格里，由管理员在“站点设置”里调整。
- 机柜进入 Error 后不会自己恢复；原因消除后要“重新执行机柜维护”。终止维护只在机柜处于维护阶段时可用。
- 清单核对帮人在登记机柜前看清差异；登记之后它不拦截上线。
- 同一机柜同时只有一个任务，执行期间其他机柜级操作禁用。
- 有整柜泄漏的机柜：NICo 自动强制下电，并拒绝上电。
- 删除机柜只删除机柜对象，不处理成员设备：要先删除实例，再把成员设备逐台退役，然后才能删除。删除前逐项显示这些前提是否满足。
- 下电、重启、有实例时的固件更新、终止维护和删除机柜是高风险操作，要输入机柜 ID。
- 待定：上线任务与 NICo 自动的机柜维护同时进行时如何衔接，要在模拟环境里实测后确定。

### 规则与门控

- 这一页只列已纳管的设备。只在规划里、还没有纳管的设备在“设备清单”里；纳管在“设备发现”里做。
- “需要处理”只用 NICo 的信号：处理失败、有健康告警。
- 已纳管但 NICo 还没有建立对象的设备，运行状态写明它在等哪一步：待一键匹配、待登记机柜、等待上线，不属于机柜的服务器是首次安装时接管。这时可以一键匹配、更新 BMC 地址和改系统配置，不能做电源等操作。
- 一键匹配只改平台里的设备配置，不动设备，也不写 NICo；一次 1–50 台。规划改了之后要再匹配一次。BMC 规划地址匹配进来之后还没有生效，要另外执行“更新 BMC 地址”。
- BMC 地址：设备接电时拿到的是 DHCP 地址池里的任意一个地址；纳管之后才能按规划更新。规划地址要在带外管理子网内，不能是网关，不能和已有地址或其他设备的规划重复。
- 更新 BMC 地址是人手动发起的，不会自动执行。一次 1–256 台。通过检查的设备依次走四步：检查地址与身份、更新 BMC、验证新地址、同步管理记录；没通过的写明原因，不执行。中断时有两个恢复入口：更新请求还没有发给设备的，“重新检查并更新”；BMC 已经在用新地址、只是管理记录没有同步完的，“核对并完成同步”。地址切换时管理连接可能短暂中断；不触发装机，不影响主机上运行的系统。
- 不属于机柜的服务器没有“上线”这一步：纳管后不上电，第一次装系统时由 NICo 上电接管。
- 系统配置是一台服务器下次装系统时用的配置，字段沿用现有产品：启动网卡 MAC、管理 IP、管理子网、主机名、当前安装方案、下次安装系统盘和设备覆盖设置。每一项都有默认值，不填也能装；其他网口不管理也不显示。入口在设备清单、这一页和新建安装任务的核对列表里，是同一个弹窗、同一份数据。第一次装机和以后重装用的是同一份，改一次一直有效。
- 退役是逐台设备的操作。有实例的服务器不能退役。
- 有实例的服务器，关机等操作要输入序列号确认。
- 只读角色的操作按钮禁用。

### 规则与门控

- 装系统按台进行：一台机器一个实例。可以跨机柜选择，也可以选不属于机柜的服务器。每批最多 50 台。
- 安装条件检查是单独的第三步，在核对完配置之后才做，因为它比较耗时；修改配置不会反复触发它。检查分三组：设备身份、安装配置、操作系统材料。检查项沿用现有产品，按设备的情况分两套。已经就绪的机器：当前 BMC 认证及主机序列号；机器就绪、没有实例、系统盘与网络规划；逐机安装配置与安装材料。还没有被 NICo 接管的服务器：BMC 身份、启动网络配置及接管保护；设备规划、主机名与安装方案；机器接管与就绪（执行前确定）；目标盘（执行前确定）；安装材料可以取到、长度与登记一致。任何一台的任何一项不通过，整批不能提交。
- 检查结果 15 分钟内有效。提交时已经过了 14 分钟的，先重新检查一次再提交。
- 系统盘按安装方案的选盘规则解析，必须解析出唯一的一块盘；解析不出时在核对配置的列表里标红，点它在系统配置里指定系统盘后才能进入检查。
- 配置没有改动时，从核对配置回到第三步沿用上一次的检查结果。检查通过只表示当时可以执行：提交时服务端再检查一次配置和占用，执行前另做安装材料的完整摘要校验。
- “当前系统”按需查询，只读：用来在覆盖系统盘之前看一眼设备上现在是什么。状态用词：未查询、已关机、无 SSH 无法访问、已读取系统、发现 / 安装环境。
- 每台设备的安装配置归设备管理里的“系统配置”维护，新建安装任务只引用和核对；在核对页点一台设备，打开的就是它的系统配置，写入的也是同一份数据。字段沿用现有产品的系统配置：启动网卡 MAC、管理 IP、管理子网、主机名、当前安装方案、下次安装系统盘，以及收起的设备覆盖设置。
- 提交时把每台设备当时的配置存成这次任务的快照。之后再改系统配置，不影响已经提交的任务，只影响下一次装系统。
- 配置都有默认值，默认情况下不需要填写：主机名按序列号生成（host-<序列号小写>-<设备记录编号前 8 位>，规则沿用现有产品；现有产品要打开系统配置保存一次才生效，这里直接生效），安装方案用这种架构的默认方案，系统盘按方案的选盘规则。
- 主机名可以单独填写：1–63 个小写字母、数字或连字符，首尾是字母或数字，不能和其他设备或已有的实例重名。
- 管理口来自设备规划：纳管后“一键匹配”把规划里的启动网卡 MAC、管理 IP 和管理子网写进系统配置。没有匹配、也没有填启动网卡 MAC 的设备，安装条件显示“待准备 · 请完善安装配置”。其他网口平台不管理，也不显示。
- 安装方案按架构匹配：只列出已发布、架构与设备一致的方案。
- 带维护标记、已隔离或有阻止分配告警的设备不能选；机柜未就绪、有整柜泄漏或有进行中任务时，柜里的设备不能选。原因写在每一行上，平台不提供绕过。
- 不属于机柜的服务器纳管后还没有被接管的也可以选，安装条件显示“自动准备”：安装任务的第一步“准备设备”让 NICo 给它上电并接管，之后才写系统盘。它的“机器就绪”和“系统盘”两项标为“执行前确定”，不算失败；首次接入会清理全部磁盘，要另外勾选确认。
- 所有实例建在站点的默认租户下，页面上不出现租户；平台不向其他平台分发机器。
- 同时安装的台数在提交时填写，默认 5，可以填 1–50。
- 阶段用词沿用现有产品：等待执行、准备设备、安装前检查、同步设备规划、安装系统、启动系统盘、安装验收、GPU 环境检查、重启验收、完成。“同步设备规划”把这次任务冻结的系统配置写给 NICo。
- 安装验收八项：安装器成功、主机配置、系统盘与 EFI 分区验证、网络配置、DNS / HTTP / NTP 连通、SSH 连通、GPU 环境检查、重启验收。
- 设备暂停时的处理入口沿用现有产品：继续准备设备、重新检查并继续、重试安装、开始验收、结束任务。
- 状态用词：待执行、执行中、已完成、需处理、已终止。
- 失败的设备暂停等待处理，不影响同批其他设备。

### 规则与门控

- 平时不会在后台自动更新固件：设备版本与基线不同只标出来。
- 子网、DHCP 和引导服务地址在“网络规划”里维护。

## 配置 › 固件基线

把固件版本从操作参数里拿出来，变成可审计的档案。操作人只选基线。

- 入口：配置 → 固件基线
- 设计章节：6.6 档案与审计；10 非功能设计（固件基线的来源）
- 现有页面：新增页面。现有服务器运行状态里的“固件”表是实际版本的来源
- 脚本：`pages/profiles.js`，路由 `#baselines`

### 功能点

| 编号 | 功能点 | 类型 | 说明 |
| --- | --- | --- | --- |
| 1 | 基线列表 | 新增 | 基线、适用的机柜规格、发布日期、使用中的机柜。 |
| 2 | 偏差统计 | 新增 | 版本与推荐基线不同的设备数量，对应设备页的“固件与基线不同”筛选。 |
| 3 | 只读说明 | 新增 | 基线在这里只读；更新固件从机柜发起。 |

### 字段

| 字段 | 来源 | 说明 |
| --- | --- | --- |
| 固件基线 | 站点为机柜规格配置的固件清单 | 计算托盘的 BMC 和 UEFI、交换机的 BMC，以及 NVOS 的目标版本 |
| 版本不同的设备 | 设备实际版本对比推荐基线 | 只比较 NICo 读得到的部件：NVOS 和供电框没有可读的版本 |

### 规则与门控

- 固件只在两种时候更新：新机柜上线（机柜规格配了固件清单时），和人提交固件更新。平时不会自动更新，版本不同只标出来。
- 提交固件更新时，版本已经与所选基线相同的设备会跳过。
- 没有为某个机柜规格配置固件清单时，这个规格的机柜上线时不会更新固件。

## 配置 › 安装方案

可复用的系统安装配置。合并现有的操作系统材料和安装方案。方案按架构区分，新建安装任务时逐台选用。

- 入口：配置 → 安装方案
- 设计章节：6.6 档案与审计
- 现有页面：安装方案页（表头、状态、行操作沿用）与操作系统页（ISO 与 OS 版本）合并
- 脚本：`pages/profiles.js`，路由 `#os-templates`

### 功能点

| 编号 | 功能点 | 类型 | 说明 |
| --- | --- | --- | --- |
| 1 | 方案列表 | 沿用 | 名称 / 版本、默认系统 / 安装器、分区 / 默认登录配置、状态 / 引用、操作，与安装方案页一致。 |
| 2 | 状态 / 引用 | 沿用 | 草稿、已发布、已停用。已发布的版本只读，修改要建新版本。 |
| 3 | 不做逐机配置 | 调整 | 方案里去掉设备覆盖设置和逐机网卡规划。逐台不同的内容（主机名、用哪个方案、系统盘的例外）在设备管理的“系统配置”里维护，都有默认值。 |

### 规则与门控

- 新建和发布方案需要管理角色。
- 安装任务只能选择已发布的方案，并且方案的架构要和设备一致。
- 编辑弹窗沿用安装方案的基本信息、系统盘选择、分区布局、默认登录配置、安装验收。
