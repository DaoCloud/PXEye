# 整机柜运维前端设计稿

[English](README.md) · **简体中文** · [设计文档](../README.zh-CN.md)

面向 GB200 / GB300 整机柜的 PXEye 前端页面设计。它是前端实现的参考：页面可点击，样式和写法与现有产品一致，每个页面带自己的功能说明。数据全部是编写的示例，不连接任何站点，也不是已实现的功能。

## 打开

设计稿有两个入口，页面完全相同，区别只在是否带接口内容：

| 入口 | 用途 | 内容 |
| --- | --- | --- |
| `index.html` | 对外展示和评审 | 页面、功能点标注、页面说明。不加载任何接口内容 |
| `internal.html` | 内部实现参考 | 在对外版的基础上，多出顶栏的“接口契约”页，以及页面说明面板末尾的“NICo 接口”和“前置资源” |

在检出的仓库里用浏览器直接打开，不需要构建和服务器。页面直接引用 `src/pxeye/web/` 下的产品样式文件，所以要在仓库里打开，不能单独拷走这个目录。

## 页面说明在哪

每个页面的说明（定位、入口、功能点、字段、规则、弹窗）写在该页面脚本的 `spec` 里，和页面的渲染代码在同一个文件。它有三种看法，来源只有这一份：

| 看法 | 在哪 | 用途 |
| --- | --- | --- |
| 页面右侧的“页面说明”面板 | 顶栏“页面说明”，或面板收起后右侧的竖条 | 边点边看当前页面的说明。面板可以收起、展开和加宽，始终把页面推开，不覆盖页面内容 |
| 页面上的编号标注 | 顶栏“功能点标注” | 编号与说明里的功能点一一对应；鼠标移到说明上会高亮页面元素 |
| 全部页面说明 | 顶栏“全部页面说明”，或 [page-spec.zh-CN.md](page-spec.zh-CN.md) | 评审和打印 |

`page-spec.zh-CN.md` 是生成的文件，不要直接修改。它不含接口内容，可以对外。改了页面或它的 `spec` 之后重新生成（同一条命令也生成 `internal.html` 和接口契约）：

```bash
node docs/design/frontend/tools/build-spec.mjs
```

功能点的类型：**沿用**表示与现有产品页面一致，**调整**表示在现有基础上修改，**新增**表示现有产品没有。界面是简体中文，页面说明随界面只有简体中文。

## 接口契约（实现参考版）

接口契约是内部实现参考，不用于对外展示。它只由 `internal.html` 加载，全部内容在 `contract.js` 里，页面脚本里不写接口。它回答四个问题：

- **功能需要部署什么。** 组件表列出每个组件提供什么、缺了它哪些功能不可用。一个接口需要哪些组件，由它的类型、执行方和前置资源推出，不另外维护对照。
- **页面调用哪些接口。** 每个接口记录它属于哪一类（Core gRPC、REST、指标）、对应的命令行、请求参数、用到的字段、由谁执行，以及在 NICo 源码里的出处。`PAGE_CALLS` 记录每个页面用到哪些接口和用途。
- **页面要有数据，必须先有什么。** NICo 的资源连成一张依赖图，每个资源写明怎么得到、依赖什么，以及没有真实整机柜时怎么准备。
- **设计需要、NICo 没有直接提供什么。** 缺口表记录源码里的实际情况和可选的处理方式。

它有三种看法：

| 看法 | 在哪 | 用途 |
| --- | --- | --- |
| 页面说明面板里的“需要的组件”“NICo 接口”和“前置资源” | `internal.html` 里任一页面右侧的面板 | 看当前页面需要的组件、用到的接口和要先准备的资源 |
| 接口契约页 | `internal.html` 顶栏的“接口契约”，或 [interface-contract.zh-CN.md](interface-contract.zh-CN.md) | 完整的组件表、资源依赖、接口清单、各页面的对照和缺口 |
| `contract.json` | 与契约同时生成 | 给采集和回放工具读取 |

每个接口带一个证据等级：**定义**表示只读过源码里的定义，**模拟**表示在模拟环境里调用过，**现场**表示在真实整机柜环境核对过。核对之后在 `contract.js` 里改这个接口的 `evidence`，再重新生成。契约对应的 NICo 源码版本写在 `contract.js` 的 `CONTRACT_SOURCE` 里，换版本时逐项重新核对。

生成器会自检：对照里的页面不存在、页面引用了未定义的接口、接口引用了未定义的资源、定义了却没有页面使用的接口，都会列在契约末尾。

## 左侧菜单

菜单按“对象直达”组织：设备按类型各有自己的入口，不需要先进机柜；机柜是关联与汇总视图。带子菜单的菜单项可以折叠：点文字进入该页面并展开，点箭头只切换折叠。

| 分组 | 菜单项 |
| --- | --- |
| 运维 | 机柜管理；NVLink 域管理；设备管理（子菜单：计算托盘、交换机、供电框、DPU）；健康告警；运维任务；操作审计 |
| 交付 | 机柜交付；安装任务；实例管理 |
| 接入 | 网络规划；设备清单；设备发现 |
| 配置 | 站点设置；固件基线；安装方案 |

“接入”三项按使用顺序排列：先规划网段，再导入设备清单，通电后查看设备发现。网络规划检查不通过时不能导入设备清单。

菜单名用四个字的正式名称，页面标题与菜单名一致，子菜单是设备类型名。菜单上的数字都表示需要关注的数量，不是总数。一级菜单的字号和间距与产品一致，颜色加深、字重略增；子菜单小一号、颜色较浅。

## 用词

界面文字统一用中文，不把英文缩写和中文拼成一个词。固定用词：安装方案、交换机、机柜上线（对应 NICo 的 bringup）、就绪、序列号、开机与关机、阻止分配。三类设备统称“设备”，“计算托盘”只作为其中一类的名称。

保留原文的只有两类：产品与组件名（NICo、NVLink、RMS、Flow、BMC、PMC、NVOS、DPU、Fabric Manager），以及 NICo 状态机回报的状态值（如 Ready、Maintenance），后者按“显示状态原文”的规则不翻译。

## 结构

| 文件 | 内容 |
| --- | --- |
| `index.html` | 对外版的外壳。样式引用 `src/pxeye/web/` 下的 `styles.css`、`live.css`、`nico.css`，设计稿不带副本 |
| `design.css` | 设计稿新增的组件样式和标注层；进入实现时把新组件部分迁入产品样式 |
| `app.js` | 运行时：`registerPage` / `registerAction`、`heading` / `table` / `button` / `badge` / `modal`，签名和类名与产品的 `shared/live.js` 一致 |
| `data.js` | 示例数据和任务模拟；实现时替换为 NICo Core 与 Flow 的接口 |
| `pages/*.js` | 页面脚本，每个页面带 `spec` |
| `pages/operations.js` | 机柜、NVLink 域、设备的写操作和门控 |
| `tools/build-spec.mjs` | 生成 `page-spec.zh-CN.md`、`internal.html`、`interface-contract.zh-CN.md` 和 `contract.json` |
| `internal.html` | 实现参考版的外壳；由生成器从 `index.html` 生成，不直接修改 |
| `contract.js` | 接口契约的全部数据：资源依赖、接口清单、页面与接口的对照、缺口。只由实现参考版加载 |
| `pages/contract.js`、`contract.css` | 接口契约页、面板里的接口一节及其样式。只由实现参考版加载 |

## 讲解

右侧面板的“讲解与模拟”里有十步讲解主线和几个模拟开关：通电并发现新机柜、泄漏告警、RMS 不可用、Flow 不可用、重置示例数据。顶栏可以切换三种角色：只读不能执行任何操作；操作可以执行设备、机柜和交付操作；管理另外可以修改站点、网络和安装方案。
