# 功能与支持边界

[English](features.md) · **简体中文** · [文档中心](README.zh-CN.md)

本文描述当前代码能力。页面渲染、示例数据展示和真实硬件验证提供不同层级的证据。正式交付前，需要按照实际 NICo 版本和硬件核对流程。

## 机柜拓扑

按机柜汇总服务器、DPU 端点、NVLink 交换机和供电框，展示序列号、实际管理地址和已回报的电源状态。同类设备区域支持拖拽，显示顺序保存在 PXEye SQLite；不修改 NICo Rack 归属、U 位或布线。绿色状态点表示最近回报为开机，不代表 OS 健康检查通过。

## 发现与纳管

读取 NICo DHCP 观察到的端点，按来源网络过滤。管理员提供统一凭据，通过 Redfish 读取序列号、型号和受支持的接口，再选择纳管。发现不启动 Scout、不清盘、不装 OS。

DHCP 发现要求设备启用 DHCP，且请求能够正确转发。使用未知静态地址的控制器不能仅靠通电发现。BMC 网络不通或认证失败时，通常无法凭 DHCP 信息可靠对应现场物理设备。

## 设备与地址管理

设备管理分为设备规划、发现设备和纳管设备。设备规划使用独立的 CSV 清单，维护 SN、管理地址/MAC、管理子网 CIDR、BMC 地址/MAC及机柜，并与纳管设备配置对比。纳管后按唯一 SN 一键匹配，管理 MAC 指定真实接口，CIDR精确关联已有子网；机柜只用于对比。

服务器通过系统配置维护 hostname、目标 OS 和安装方案，并保留逐机配置版本；其他设备使用原有地址管理。字段和操作见[设备管理使用指南](user-guide/device-management.zh-CN.md)。

保存规划仅持久化产品数据和派生文件。批量操作分别执行：

| 操作 | 实际作用 |
| --- | --- |
| 一键匹配 | 将独立规划中的 BMC 目标地址、管理接口及子网写入已纳管服务器的配置；不改变运行地址。 |
| 更新 BMC 地址 | 检查目标地址和设备身份，通过受支持的 Redfish 接口改址，验证新地址并同步记录。 |
| 更新管理地址 | 操作受支持的管理端点，具体行为取决于设备类型和接口驱动。 |
| 刷新设备详情 | 读取身份和受支持的接口信息，不改变地址。 |

列表区分当前与规划地址。受支持时同步 Expected Machine 声明和接口地址记录；只在 NICo 中预留地址，不会让使用静态 IP 的控制器自行改址。这些操作不能强制所有类型设备重新发起 DHCP。

## 网络管理

页面入口、字段格式和操作步骤见[网络管理使用指南](user-guide/network-management.zh-CN.md)。

查看 NICo `NetworkSegment` 前缀、网关、MTU、接口引用和地址策略。当前新增表单提供 HostInband、Admin 和 Underlay，地址策略为动态分配；已有生效子网在当前 UI 只读，集成版本没有原位更新接口。删除生效子网受引用检查及 NICo 生命周期约束。

DHCP DNS 是租约下发给请求接口的信息。relay 的 `giaddr` 和站点配置决定请求匹配哪个网段。PXEye 不配置交换机 relay、VLAN 或 ACL。

## 操作系统管理

浏览器分块上传 ISO，或从 PXEye 服务内的只读挂载目录导入。检查大小和 SHA256，识别受支持的 Ubuntu 材料并提取 kernel/initrd。通过主机可达的材料服务发布，再登记 NICo OS 定义。可启停定义并查看引用，运行中的安装仅锁定实际使用的版本。

自制 ISO 仍需要受支持的无人值守安装器。NICo Scout 的引导材料用于发现与清理，用户 OS 材料独立管理。

## 安装方案

安装方案是 PXEye 的组合资源，不是 NICo 的同名原生对象。复用 OS 和安装默认值，按唯一匹配、容量排序、总线类型、型号或序列号 glob、容量范围选择系统盘；配置 GPT/UEFI、EFI 分区和 ext4/XFS 根分区。

适用字段以设备显式规划覆盖方案默认值，任务创建时冻结最终配置和来源。启动口和磁盘身份按具体设备解析，不假定通用网口名或盘符；匹配有歧义时阻止写盘。

## 安装执行

核对身份、网络、材料、资源占用和磁盘范围。首次安装按需准备硬件并创建 Instance，重装使用已有 Instance。生成受控 autoinstall 数据，通过 NICo 引导控制启动 PXE/iPXE，采集 SOL 输出和安装器事件。

安装后通过任务专属 SSH 身份检查 hostname、根盘、EFI、网络和安装回执，再做普通重启验证。外部写入结果未知时保留证据，通过读回或明确恢复入口继续，不盲目重放。

Scout 在业务 OS 安装前的发现环境运行。站点接入策略可能清理全部磁盘，或调整凭据、BIOS、固件；这个范围与 OS 安装写入所选系统盘不同。

## 实例与站点

查看 Instance、关联 Machine、OS 和生命周期状态。release 发起 NICo 回收，可能触发清理，不是删除页面记录。页面跟踪实际进度和回报故障。

站点设置展示 Core 连接、mTLS 客户端身份、存储和配套服务端点；名称和 Core 地址的有限修改使用当前身份验证。状态区分 TCP 可达、存在配置和协议检查。

## 当前运行范围

- 单站点、单副本、单操作员，装机串行执行。
- 无分布式队列、多站点管理和完整用户/租户 RBAC。
- 主要实机验证：Ubuntu Server 24.04、x86_64、UEFI。
- ARM64、GB200/GB300、其他发行版和 OEM 启动差异需要独立验证。
- DPU、NVLink 交换机和供电框写操作依赖实际管理接口。
