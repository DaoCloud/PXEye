# One-command fireseed installation

**English** · [简体中文](README.zh-CN.md)

## Goal

Import one PXEye/NICo offline delivery and deploy its control plane with one command. The only required input is the
absolute path to `bundle.tar.gz`; optional `--mode kind|k8s` selects the cluster mode and defaults to `kind`.
There is no installer configuration file to fill in, and no checksum, extraction directory, work directory, namespace,
release name, certificate mode, DNS/PXE/NTP addresses, or HostInband network to supply.

The first install is fixed to:

- namespace: `nico-system`
- NICo parent-Chart release: `nico`
- PXEye Service: `NodePort` `31808` (Kubernetes also allocates its ClusterIP)

In `kind` mode, the runner prefers the current `kind-*` context; otherwise it accepts exactly one Kind candidate.
In `k8s` mode, it uses the kubeconfig's current context without a name-prefix restriction and stops if that context
is missing or does not exist in kubeconfig. Select the intended context with `kubectl config use-context` before
running; the installer has no `--context` parameter.

Both modes discover the Registry, skip TLS certificate-chain/name validation for the site Registry by default,
and reuse a healthy shared cert-manager. The runner installs the bundled cert-manager
only when no cert-manager exists. A partial or unhealthy cert-manager stops the run; it is never adopted or replaced.
After the Core phase, it uses the same-namespace client Secrets and the in-cluster Core address to verify mTLS and
connect PXEye to the new Core.

## Prerequisites

The fireseed host needs Python 3.11+, PyYAML and `kubectl`; cluster nodes must already be able to pull from the site
Registry. Both modes require an existing cluster, a reachable API server and kubeconfig with installation permissions,
at least one Ready amd64 node, a usable default StorageClass with capacity for the bundled PVCs, and an available
NodePort `31808`. The site Registry must accept image pushes and Helm OCI Chart push/pull from the fireseed host.
Mode selection does not create a cluster or prepare node runtimes, storage, Registry access or network routes.

Before running, verify that Python is 3.11 or newer and PyYAML imports successfully:

```bash
python3.11 -c 'import sys,tomllib,yaml; print(sys.version); print(yaml.__version__)'
```

If `python3` points to an older interpreter (for example, on Rocky 8), use `python3.11` instead of `python3` in every
installer command below, including resume commands. Do not replace the system Python.

Put these delivery files in one directory:

```text
bundle.tar.gz          # large offline delivery
onsite-tools.tar.gz    # small bootstrap runner for the delivery tools
```

`nico-system` must be empty, except for Kubernetes' own default objects or resources managed by the `nico` / PXEye
releases created by this same run. The installer rejects residual PVCs, Secrets, Services and other namespaced
resources instead of adopting legacy four-release NICo deployments, existing PXEye, or existing data.

During installation, preflight also recognizes resources generated by this run's controllers: the webhook CA
referenced by cert-manager, Secrets issued for its Certificates, recorded Helm hooks, Vault bootstrap outputs,
and resources linked through parent UIDs. These are normal installation outputs, not residual site data.

## Run

Run the following on the fireseed host. The first command extracts only the small runner, not the large bundle.

```bash
cd /srv/nico
tar -xzf onsite-tools.tar.gz
python3 /srv/nico/onsite-tools/tools/onsite/run.py \
  --archive /srv/nico/bundle.tar.gz
```

The command above uses the default `kind` mode; `--mode kind` makes that choice explicit. To install into the
current ordinary Kubernetes context, use:

```bash
python3 /srv/nico/onsite-tools/tools/onsite/run.py \
  --archive /srv/nico/bundle.tar.gz --mode k8s
```

`--archive` remains the only required input. Namespace, release, Registry discovery and installation stages are the
same in both modes. If Registry discovery cannot find one unique endpoint from workload-image or
`local-registry-hosting` evidence, the runner stops during stage 2. Only in that exception, set
`NICO_REGISTRY_URL=http(s)://registry-host:port` before rerunning. The variable selects only the Registry endpoint;
the default policy still skips its TLS certificate-chain/name validation and must not be treated as Registry identity
verification.

## Confirm

Success ends with `PXEYE_CORE_CONNECTED` and `ONSITE_COMPLETE`. The latter means Helm is ready and PXEye has completed
an in-cluster mTLS connection to Core. Directories are derived from the archive name; for
`/srv/nico/bundle.tar.gz`, the runner creates:

```text
/srv/nico/bundle/             # extracted delivery; internal inventory verified
/srv/nico/bundle.onsite/      # progress, logs, frozen Helm recipe, private state
```

The first execution records `cluster_mode` and the selected context in the generated `install-config.json` in that
run directory. This is frozen runtime state, not a user-supplied installer configuration. Subsequent Kubernetes and
Helm commands explicitly use the recorded context.

The runner also writes a read-only `environment.sh` in that run directory for inspection and troubleshooting. It is
not an installer input; it prevents confirmation commands from accidentally using the current shell's business-cluster
context.

```bash
source /srv/nico/bundle.onsite/environment.sh
kubectl --context "$CONTEXT" -n "$NICO_NAMESPACE" get pods
kubectl --context "$CONTEXT" -n "$NICO_NAMESPACE" get service "$PXEYE_RELEASE"
cat "$(dirname "$WORK")/progress.json"
```

An unclaimed Kubernetes NodePort does not prove that the fireseed host or an external network can reach it. A Kind
cluster still needs the required port mapping at creation time, or an existing controlled access route / `kubectl
port-forward`.

## Open PXEye

After success, the runner prints the port-forward command with the resolved context and namespace. When run over
SSH, it also prints the fireseed SSH address as the browser URL. Run the printed command on the fireseed host:

```bash
source /srv/nico/bundle.onsite/environment.sh
kubectl --context "$CONTEXT" -n "$NICO_NAMESPACE" \
  port-forward --address 0.0.0.0 "service/$PXEYE_RELEASE" 31808:80
```

Keep that terminal open. Once it reports `Forwarding`, open `http://127.0.0.1:31808/` on the fireseed host or use
its reachable address and port `31808` from your browser. Ctrl+C ends the access session.

The first deployment generates a random login password. The success output also prints this retrieval command;
run it in your terminal and paste its output into the login form:

```bash
kubectl --context "$CONTEXT" -n "$NICO_NAMESPACE" \
  get secret "$PXEYE_RELEASE" -o jsonpath='{.data.bootstrap-password}' | base64 -d
```

The installer prints the command, not the password, so credentials stay out of the installation log. Helm upgrades
retain the existing password.

## Resume

After fixing an external cause, rerun the identical command:

```bash
python3 /srv/nico/onsite-tools/tools/onsite/run.py \
  --archive /srv/nico/bundle.tar.gz
```

For a run started with `--mode k8s`, keep the same flag when resuming:

```bash
python3 /srv/nico/onsite-tools/tools/onsite/run.py \
  --archive /srv/nico/bundle.tar.gz --mode k8s
```

The same run directory must retain its frozen mode and context. A different mode stops the run. In `k8s` mode,
changing kubeconfig's current context also stops the rerun instead of targeting another cluster; restore the
recorded context with `kubectl config use-context` before resuming. Do not edit the generated state to retarget a run.

Completed stages are rechecked and reused. The runner neither reimports verified Charts nor automatically unlocks a
pending Helm operation. Inspect:

```bash
tail -n 80 /srv/nico/bundle.onsite/run.log
cat /srv/nico/bundle.onsite/progress.json
```

## Initial networking boundary

This step installs only the control plane. It does not turn a Kubernetes `ClusterIP` into a physical address, create a
sample HostInband subnet, or configure DNS/PXE/NTP VIPs, DHCP Relay, LoadBalancers, switch relay, routing, ACLs, or
firewall rules. The initial Chart creates neither external boot-service endpoints nor a HostInband plan; this is not
physical-provisioning acceptance and is not a substitute for network-isolation controls.

The bundled `nico-dhcp` Deployment intentionally starts at zero replicas. Its upstream DHCP option placeholders are
not valid physical endpoints, so no Kea process is started until later site-network configuration supplies real
DNS/NTP/PXE/VIP values and explicitly enables DHCP.

Physical boot endpoints and HostInband planning belong to the subsequent PXEye site configuration: DNS/NTP servers,
PXE/DHCP-Relay external endpoints, provisioning-VLAN prefix/gateway/MTU, external Services/VIPs, and switch relay,
routing, ACL and firewall rules. Configure and validate those from the provisioning VLAN before enabling real
provisioning. Helm readiness is not physical-installation acceptance.
