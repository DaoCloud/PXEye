# Step 2: one-command Helm offline delivery

**English** · [简体中文](README.zh-CN.md)

Use the prepared directory and generated `*.helm-build.json` from [step 1](../material-prepare/README.md). Maintain one configuration file. This path packages existing images without rebuilding material images or accessing Kubernetes. The legacy `nico-materials` input remains supported and retains its material-image build behavior.

## Run

Goal: package on Linux amd64 with Python 3.11+/PyYAML, local Docker and Helm 3. Sources must be committed. Save the configuration generated by step 1 as `/srv/nico-build/helm-build.json`; its paths must refer to the actual prepared input and output root. No site Registry, namespace or network settings belong here.

Command:

```bash
python3 /srv/PXEye/offline-build/helm-bundle/build.py --config /srv/nico-build/helm-build.json
```

Confirmation, using the configured output root:

```bash
ls -la /srv/nico-build/output
```

The command validates inputs/tools, seeds a loopback Registry, composes and renders Charts, produces per-Chart relok8s bundles, compresses the delivery and reads every archived file back. Offline builders must already have the pinned Registry image and relok8s binary; otherwise the tool may download missing locked dependencies.

## Resume and logs

Goal: fix the underlying failure and rerun the identical command. No manual sequence or `tee` is required.

Command:

```bash
python3 /srv/PXEye/offline-build/helm-bundle/build.py --config /srv/nico-build/helm-build.json
```

Confirmation:

```bash
find /srv/nico-build/output -name progress.json -o -name run.log -o -name events.jsonl
```

The default version is saved per configuration. An identical invocation resumes that version; a complete version is verified and reused. Use `--version` only to create another delivery. Changed configuration, input inventory or implementation requires a new version. Old randomly named staging directories are not adopted.

Stage output identifies current work and reuse. Atomic `progress.json` stores status, attempt, timestamps, duration and failure reason. `events.jsonl` and `run.log` append history. Command logs retain real exit codes.

Failed work remains under `output_root/.<version>.building/` (visible with `ls -la`). Registry data and its port survive failed attempts; the container stops on exit and resumes the same loopback address. Existing manifests are checked by digest. Completed Chart bundles are verified by hash before reuse. Partial Chart migration/compression restarts at that stage, not a byte offset. A conflicting port stops recovery rather than silently changing references. There is no global Docker cleanup.

## Output

Goal: deliver the archive and checksums; retain diagnostic records on the builder.

```text
output_root/
  .active-<config-hash>.json
  .<version>.building/             # failure evidence
  <version>/
    bundle.tar.gz
    SHA256SUMS
    build-result.json
    progress.json
    events.jsonl
    run.log
    logs/
    *-relok8s.log
    render/
    bundle/
      bundle.json
      charts/
      relocation/
      profiles/
      manifests/
      tools/helm
      tools/relok8s
      tools/verify.py
      tools/onsite/run.py
      tools/onsite/run-config.example.json
      docs/
```

The archive contains only delivered `bundle/` contents, under the configured `bundle_id`. Successful publication removes temporary Registry/build data. Logs and progress remain outside the archive. For a version deliberately named `field-01`:

Commands:

```bash
cd /srv/nico-build/output/field-01
sha256sum -c SHA256SUMS
python3 bundle/tools/verify.py bundle
```

Confirmation:

```bash
cat build-result.json
cat progress.json
```

Continue with [step 3](../onsite/README.md). Packaging is distinct from control-plane readiness, strict mTLS, material HTTP, physical networking and OS provisioning acceptance. The old UI does not automatically consume the OCI catalog.
