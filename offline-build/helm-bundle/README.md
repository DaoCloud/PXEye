# Step 2: build the offline delivery

**English** · [简体中文](README.zh-CN.md) · [Overview](../README.md)

**Goal: package prepared images and Charts for delivery. Run on the builder.** No Kubernetes or site configuration is needed. The preferred path does not rebuild material images.

## Stages

| Stage | Action | Key point |
| --- | --- | --- |
| Validate inputs/tools | Verify prepared hashes and locked tools | Use the configuration generated by step 1 |
| Stage images | Populate a local loopback Registry | Reuse manifests by digest |
| Render Charts | Validate configuration and actual image consumers | Reject images outside the delivery |
| Package with relok8s | Collect images per Chart | Verify and reuse completed Chart bundles |
| Compress/verify | Compress and read back every delivered file | Publish a complete version directory |
| Export onsite tools | Create the small execution kit | No missing bootstrap scripts onsite |

## Run one script

Goal: reuse the selected input/version without rebuilding image lists. See [requirements](../README.md#requirements-and-paths).

**Execute the complete command printed after step 1's `NEXT_COMMAND`.** In a new terminal, select the actual path printed after `HELM_BUILD_CONFIG`:

```bash
read -r -p 'Paste the HELM_BUILD_CONFIG absolute path: ' HELM_CONFIG
python3 /srv/PXEye/offline-build/helm-bundle/build.py --config "$HELM_CONFIG"
```

Confirmation: `HELM_BUILD_COMPLETE`; `DELIVERY_FILES` lists the three files to copy onsite.

The generated configuration contains prepared/output paths, bundle name, material switches and tools. Adjust local paths if changing builders. Missing locked dependencies may be prepared online; cache the tools and Registry image before a fully offline build.

## Deliver three files

```text
output_root/<version>/
  bundle.tar.gz             # Charts, relok8s image bundles, inventories and tools
  onsite-tools.tar.gz       # step-3 runner and configuration template
  SHA256SUMS                # checksums for both archives
  build-result.json
  progress.json
  events.jsonl
  run.log
  logs/
  bundle/                   # complete extracted delivery tree
```

**Copy the first three files to `/srv/nico/` on the fireseed host, then follow [step 3](../onsite/README.md).** Do not transfer prepared data, caches or build Registry storage. The large archive contains a full inventory; large material files reside in images.

## Recovery and logs

Fix the cause and rerun the original command. The version is saved per configuration. Completed images, Chart bundles and archives are verified before reuse; incomplete stages restart. Completed versions print `HELM_BUILD_REUSED`. Use `--version` only to create another delivery.

| Location | Purpose |
| --- | --- |
| output_root/.<version>.building/ | Retained failure state; visible with `ls -la`; do not delete |
| progress.json | Current stage, attempts, duration and failure reason |
| events.jsonl / run.log | Appended stage history and terminal output |
| logs/ and *-relok8s.log | Command output and exit results |

Recovery is stage-based, not byte-offset transfer. Changed inputs/configuration/revision require a new version. Registry containers stop on exit; failed runs retain data/port for recovery, while successful runs remove temporary data.

Legacy `nico-materials` input remains supported with its older material build behavior. New tasks should use step-1 prepared output. References: [relok8s 0.5.4](https://github.com/vmware-tanzu/asset-relocation-tool-for-kubernetes/tree/v0.5.4), [Helm OCI](https://helm.sh/docs/v3/topics/registries/).
